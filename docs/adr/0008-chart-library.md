# ADR-0008: チャートライブラリを採用せず、サーバー側で SVG を直接描く

- ステータス: Accepted
- 日付: 2026-09-20
- 関連: ADR-0004（指標の算出定義）, ADR-0007（Node + SQLite の自ホスト）, ADR-0001（デプロイ検出ルール）, #19

## 文脈

ADR-0004 で「**データ点が少ない週は値を出さず、線も繋がない**」と決めた。
さらに ADR-0001 で `merge_only` を既定にした結果、**欠損週は例外ではなく通常の表示状態**になる。
つまり「欠損で線が切れる」は端のケースではなく、主要な表示経路そのものである。

多くのチャートライブラリは、欠損を落として前後の点を直線で繋ぐ（＝補間する）。
補間された線は「その週にもデータがあった」という嘘をつくので、
**既定で補間するライブラリ、あるいは補間しない設定が壊れやすいライブラリは採用できない。**

ADR-0007 により実行環境は Node + Docker、画面は Hono + JSX のサーバーサイドレンダリングで、
チャートだけはクライアント JS を使ってよいことになっている。

本アプリがチャートに要求するものは、実際には次で全部である。

1. 週次の折れ線（x 軸は JST 月曜始まりの週、最大 52 点程度）
2. **欠損週で線を切る**
3. 中央値の主線に p75 / p90 を薄く重ねる（最大 4 系列・ADR-0004）
4. 点のクリックで指標詳細画面へ遷移する（#20 → #21）
5. ライト / ダークどちらの背景でも読める

ズーム・パン・ブラシ選択・アニメーション・任意のチャート種別は要求に含まれない。

## 決定

1. **チャートライブラリを採用しない。** 依存を 1 つも増やさず、
   **Hono JSX でサーバー側に SVG を直接出力する。**
2. 共通コンポーネントを `src/server/views/chart.tsx` の `WeeklyLineChart` として 1 つ持ち、
   #20（サマリ）と #21（指標詳細）はこれを使う。
3. **クライアント JS を使わない。** 点の遷移は SVG の `<a href>`、
   値の表示は `<circle>` 内の `<title>`（ブラウザ標準のツールチップ）で実現する。
4. **欠損週の扱いは描画より前の一箇所（`toSegments`）に閉じる。**
   値の列を「欠損で区切られた連続区間」に分割してから、区間ごとに別々の `<path>` を出す。
   区間をまたぐ線分はそもそも生成されない。
5. **欠損で線が切れることは、SVG 文字列を検査する自動テストで固定する**
   （`src/server/views/chart.test.tsx`）。週ごとの目盛り `<line data-week>` から各週の x 座標を読み、
   欠損週の x をまたぐ線分が 1 本も無いことを座標レベルで検査する。
6. 系列色は**青 1 色相の順序尺度**（中央値 → p75 → p90 と淡くなる）とし、
   ライト / ダークそれぞれの背景に対して検証した段を使う。色だけに頼らないよう、
   主線と補助線は太さも変え、2 系列以上では必ず凡例を出す。

## 理由

**要求がライブラリの守備範囲より小さい**: 上の 1〜5 がすべてで、実装は 200 行程度の SVG 生成に収まった。
このためにライブラリを入れると、得られるもの（軸・目盛り・凡例）より、
持ち込まれるもの（依存ツリー、SSR のための DOM 代替、ライブラリ固有の設定の学習）のほうが大きい。

**「補間しない」を設定ではなく構造で保証できる**: ライブラリを使う場合、補間しないことは
オプション（`spanGaps` 相当）や入力データの作り方に依存し、
**ライブラリの更新や呼び出し側の変更で静かに壊れうる**。自前で書けば、
欠損をまたぐ線分を生成する経路が存在しない。ADR-0004 の決定がコードの構造そのものになる。

**SSR と噛み合う**: Hono JSX はそのまま SVG 要素を出力できる。
サーバーで完結するので、クライアント JS も hydration も要らない。
ADR-0007 の「1 コンテナ・1 プロセス」の構成に何も足さない。

**点からの遷移が素直**: SVG の `<a href>` は普通のリンクとして動く。
JS を切っても、キーボード操作でも、新しいタブで開く操作でも動く。

**ネイティブ依存を増やさない**: `better-sqlite3` 以外にビルドが必要な依存を持ち込まない、
という制約を最初から満たす（canvas 系は満たせない。下記）。

**色を 1 色相の順序尺度にする**: 中央値 / p75 / p90 は独立したカテゴリではなく、
同じ指標の分位点の並びである。カテゴリ配色を割り当てると無関係な 3 本に見える。
淡くなる同一色相なら「同じものの裾」であることが色から読める（ADR-0004 の「薄く重ねる」）。

## 検討した代替案

### Observable Plot（次点。乗り換えるならこれ）

実際に `@observablehq/plot` + `linkedom` で Node 上のレンダリングを試した（2026-09-20）。

- **欠損で線は切れる。** `null` を含む系列で `d` が `M98,170L214,370M446,20L562,220` のように
  サブパスに分かれ、欠損区間は繋がれなかった
- **`href` チャンネルがあり**、点が `<a href>` で包まれる。#20 / #21 の遷移に使える
- **SSR には DOM の代替が要る。** `Plot.plot({ document })` に加えて `globalThis.document` の
  差し込みが必要で、これは Plot が第一に想定する使い方（ブラウザ）ではない
- **依存が重い。** Plot + linkedom で **62 パッケージ / 17 MB**（d3 系がぶら下がる）

却下の理由は「できないから」ではなく、**上の要求 1〜5 に対して割に合わないから**である。
要求が増えたとき（対数軸、ビン、ブラシ選択、チャート種別の追加など）の**第一候補として記録しておく**。
`WeeklyLineChart` の props（週の列 + 系列 + `pointHref`）を保つ限り、内部だけ差し替えられる。

### Chart.js

- 欠損自体は扱える（`spanGaps` の既定は false で、`null` の点で線は切れる）
- **canvas に描くため、サーバーで SVG を吐けない。** SSR するには `node-canvas` 系（ネイティブ依存）が要り、
  `better-sqlite3` 以外にビルドの要る依存を増やさないという条件に反する
- クライアント JS 前提になり、ADR-0007 の構成に JS バンドルの配信を足すことになる
- **点のリンクが素の `<a>` にならない。** canvas 上の当たり判定を JS で書くことになり、
  キーボード操作・新しいタブで開く・JS 無効時のどれも自前で面倒を見る必要がある

却下。「欠損を繋ぐから」ではなく、**SSR・ネイティブ依存・遷移の 3 点**で外れる。

### uPlot

軽量（〜50 KB）で欠損も扱えるが、canvas ベースでクライアント JS 前提という点は Chart.js と同じ。
サーバーで SVG を吐けないため却下。

### Vega-Lite / Vega

宣言的で、Vega の SVG レンダラーを使えばサーバー側でも SVG を吐ける。
ただし要求に対して仕様も依存も大きすぎる（ランタイム一式が乗る）。却下。

### d3-shape + d3-scale だけを使う（DOM 無しで path 文字列を作る）

`line().defined()` で欠損を切った `d` 属性を DOM 無しで生成できるため、SSR とは噛み合う。
それでも軸・目盛り・凡例・リンクは自前で書くことになり、
**自前で書く量はほとんど減らないのに依存だけ増える**。今回書いたスケールは
「等間隔に並べる」「0 起点で目盛り幅を丸める」の 2 つだけで、d3-scale を入れるほどの複雑さが無い。却下。
自前のスケール計算が膨らんできたら、この 2 パッケージだけ足すのが最も安い次の一手になる。

## 結果・影響

- **軸・目盛り・凡例・レイアウトの面倒は自分で見ることになる。**
  現在は y 軸（0 起点・目盛り幅を 1/2/2.5/5/10 × 10ⁿ に丸める）、x 軸（週ラベルの間引き）、
  凡例、空データ表示までを持っている。ここが膨らみ始めたら Observable Plot への乗り換えを検討する
- **ツールチップはブラウザ標準の `<title>` のみ。** 表示までに時間差があり、
  タッチ環境では出ない。クライアント JS を足さないための意図的な妥協で、
  週ごとの詳細は #21（指標詳細画面）が引き受ける
- **欠損週は「線が無い」だけでなく、x 軸の目盛りを破線にして明示する。**
  ADR-0004 は値を出さないと決めただけだが、#20 の議論（収集が壊れている期間と
  デプロイが無かった期間が同じ空白に見える）と同じ問題がここにもあるため、
  「その週は存在するが値を出していない」ことを図の中でも区別できるようにした
- 系列は**最大 4 本**を想定する（色スロットが 4 つ）。それ以上は色が重複する。
  ADR-0004 の指標定義は中央値 + p75 + p90 の 3 本なので、当面足りる
- `public/` 等の静的アセットは増えない。CSS はコンポーネントが自分で持つため、
  #20 / #21 はレイアウトに手を入れずにチャートを置ける
